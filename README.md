# Hublify Launchpad

Tu dois créer la première base fonctionnelle et professionnelle de l’application HUBLIFY pour le compte de TECHTRUST AGENCY.

Tu interviens comme une équipe composée d’un product designer senior, d’un UX designer, d’un développeur React/TypeScript expérimenté et d’un product manager spécialisé dans les logiciels SaaS B2B.

L’objectif n’est pas de créer une simple landing page ni une démonstration superficielle.

L’objectif est de transformer progressivement la maquette actuelle V2 Redris en une véritable application Hublify cohérente, navigable, responsive et techniquement propre, qui pourra ensuite être reprise et renforcée par l’équipe de développement de TechTrust Agency.

==================================================
1. CONFIDENTIALITÉ ABSOLUE
==================================================

Ne jamais afficher publiquement le nom Lovable ni aucune mention d’un outil de génération, de no-code ou de low-code.

Ne jamais ajouter dans l’application :

- « Built with Lovable »
- « Made with Lovable »
- « Powered by Lovable »
- « Generated by AI »
- un logo Lovable ;
- un badge Lovable ;
- un lien Lovable ;
- une mention d’un générateur ;
- une mention d’un outil no-code ;
- une mention indiquant que le produit a été généré automatiquement.

Cette règle s’applique :

- au footer ;
- aux métadonnées ;
- au titre des pages ;
- aux descriptions ;
- aux textes visibles ;
- au favicon ;
- au manifest ;
- aux écrans d’erreur ;
- aux e-mails simulés ;
- aux commentaires publics ;
- aux fichiers publics ;
- aux pages de connexion ;
- aux pages de chargement ;
- aux URL internes ;
- aux données de démonstration.

L’identité publique doit être uniquement :

HUBLIFY

L’identité de l’équipe technique est :

TECHTRUST AGENCY

Ne pas afficher TechTrust partout dans l’interface destinée aux utilisateurs. TechTrust est le responsable technique du produit, pas nécessairement la marque commerciale visible par les utilisateurs.

Aucune mention de l’outil utilisé pour construire la première version ne doit être intégrée au produit ou à la documentation publique.

==================================================
2. CONTEXTE DU PROJET
==================================================

Hublify est le nouveau nom du projet anciennement appelé REDRIS.

Le fichier appelé « V2 Redris » est actuellement la maquette principale et la source visuelle la plus récente.

Cependant :

- un écran présent dans la maquette n’est pas automatiquement validé ;
- une fonctionnalité dessinée n’est pas automatiquement à développer immédiatement ;
- certaines données sont fictives ;
- certains écrans peuvent être des variantes ;
- certains écrans peuvent être des inspirations ;
- certaines fonctionnalités peuvent appartenir à une version future ;
- certaines règles métier ne sont pas encore définies.

Il faut donc utiliser la maquette comme référence visuelle et fonctionnelle, sans la reproduire aveuglément.

Lorsque plusieurs versions d’un écran existent :

1. identifier celle qui paraît la plus récente et cohérente ;
2. conserver une seule version propre ;
3. éviter les doublons ;
4. documenter les ambiguïtés ;
5. ne pas inventer silencieusement une règle métier.

Le nom REDRIS ne doit jamais apparaître dans l’application finale.

Toutes les références visibles doivent être remplacées par Hublify.
